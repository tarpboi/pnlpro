算法交易（algorithmic trading）是指用计算机程序按照事先写好的规则来决定、下达或管理交易。它的范围很广：小到两条均线交叉就买入的简单脚本，大到在主要交易所承担每日相当大一部分成交量的机构系统。算法能消除人性中的某些弱点，比如犹豫和冲动，但也会带来新的问题：数据错误、隐藏的程序漏洞，以及只在过去有效的策略。

核心要点

  • 算法的好坏取决于其背后的想法、数据和测试；自动化本身并不会创造优势。
  • 标准流程是：想法、数据、回测、模拟交易、小规模实盘，再到持续监控。
  • 散户在速度上无法与机构竞争，因此现实可行的散户优势来自耐心、小众市场或精细的执行。
  • 交易成本和过拟合是策略在测试中看似盈利、实盘却亏损的两个最常见原因。
  • 大多数自动化散户策略都会失败，而一个有效了多年的策略也可能失效。

算法交易的含义

描述计算机驱动交易的术语有好几个，含义相互重叠：

术语 含义
算法交易 由程序按预设规则生成或管理订单的任何交易
系统化交易 按固定规则交易，不论下单的是人还是计算机
量化交易 基于数据的统计与数学分析构建的策略
自动化交易 程序直接发送订单，无需人工逐笔确认
高频交易（HFT） 持仓时间极短、以速度取胜的一个子类
执行算法 将大额订单拆分为小单以降低成本的程序，与交易决策的依据无关

它们的共同点在于规则是明确的。主观交易者可能会说“这张图看起来很强”。系统化交易者则必须把“强”定义得足够精确，精确到计算机能够测试，例如“收盘价高于200日均线，且20日收益率为正”。

这种精确性正是最大的好处。规则可以在多年历史数据上测试、度量和改进，感觉却不行。

散户与机构算法交易的区别

职业机构与散户算法交易者的处境截然不同。了解这些差异，有助于你选择能打赢的仗。

因素 机构 散户
资金 数百万到数十亿 数百到数十万
速度 微秒级，服务器托管在交易所旁边 通过互联网，毫秒到秒级
数据 完整订单簿行情、另类数据、干净的历史数据 券商或交易所 API、免费或低成本的历史数据
成本 协商费率、返佣 零售佣金、点差、平台费
人员 研究员、工程师和风控团队 通常只有一个人
优势 规模、速度、研究深度 体量小、灵活、可参与大基金忽略的小众市场

大型基金很难交易规模小、流动性差的市场，因为它们的订单会推动价格。手握几千美元的散户交易这些市场则没有这个问题。这是小交易者为数不多的结构性优势之一。速度则不是：在延迟上与高频交易公司竞争，是散户注定会输的比赛。

算法交易的流程

大多数成功的系统化交易者都遵循某种形式的相同流程。跳过步骤，往往就是亏钱的开始。

1. 想法

策略始于一个假设：价格为什么应当以某种方式运动。好的想法通常有经济学上的理由：有人被迫交易（指数再平衡、追加保证金），有人因承担风险而获得报酬（类似保险的策略），或者人们对信息反应迟缓。常见的策略类型包括趋势跟踪、均值回归、配对交易与统计套利、套利和做市。

2. 数据

你需要与实际交易相匹配的历史数据：正确的品种、正确的频率，以及足以涵盖不同市场环境的历史长度。数据必须经过拆股和分红调整，包含后来破产的公司，并且时间戳准确。市场数据一文介绍了数据来源与清洗。

3. 回测

回测是模拟规则在历史数据上的表现，并计入手续费和滑点。它会得出总收益、夏普比率和最大回撤等指标。回测是证据，而不是证明。这一阶段最大的危险是过拟合：不断调整规则，直到它贴合了过去的噪声。

4. 样本外测试与模拟交易

在投入资金之前，应先用策略从未见过的数据检验，再进行模拟交易（paper trading，即在实时价格上模拟下单）。模拟交易能发现回测发现不了的问题，例如 API 错误、数据缺失，以及实际上不会成交的订单。

5. 小规模实盘

真金白银会暴露最后一层成本：滑点、部分成交、系统宕机，以及你自己的心态。起始仓位要小到即使彻底失败，也只算一次可以接受的学费。

6. 监控与维护

实盘策略需要每天检查。把实盘结果与回测对同一时期的预测进行比较，差距越拉越大就是警告信号。随着市场变化、其他交易者发现同样的优势，策略会逐渐衰减，所以要提前设定停用标准，例如“回撤超过回测最大回撤的1.5倍就停止”。

编程语言与平台

没有唯一正确的工具。选择取决于所交易的市场和所需的速度。

选项 典型用途 说明
Python 研究、回测、大多数散户机器人 生态庞大（pandas、NumPy、scikit-learn）；对于秒级或更慢的策略速度足够
C++、Rust、Java 低延迟、高吞吐系统 更快、更可预测，但开发更慢
C# NinjaTrader（NinjaScript）和 cTrader 等平台 在散户期货和外汇领域很常见
MQL4/MQL5 MetaTrader 智能交易系统（EA） 在散户外汇和差价合约（CFD）领域广泛使用
Pine Script TradingView 策略与警报 适合快速验证基于图表的规则；做完整自动化能力有限
EasyLanguage TradeStation 在散户系统化交易者中历史悠久

大多数散户用 Python 做研究，然后要么用 Python 运行机器人，要么使用平台自带的语言。关于架构、交易所 API 和安全控制，参见搭建交易机器人。

实例：成本决定一切

假设一个短线策略每年交易200次。扣除成本前，回测显示每笔交易平均盈利0.10%。

  • 毛收益：200 × 0.10% = 每年20%（简单相加，不计复利）。
  • 成本：假设点差、手续费和滑点合计每个来回0.08%，即每年200 × 0.08% = 16%。
  • 净收益：20% − 16% = 每年4%。

现在假设实盘滑点比预想的稍差，每个来回为0.12%。成本变为200 × 0.12% = 24%，净结果为20% − 24% = 每年−4%。成本假设上的一个小误差，就让盈利策略变成了亏损策略。

同样的优势如果每年只交易20次、每笔1.0%（成本同为0.08%），净收益为20 × (1.0% − 0.08%) = 18.4%。这条教训具有普遍性：策略交易越频繁，每笔交易的优势相对于成本就必须越大。这就是高换手率的散户策略经常失败的原因。交易成本一文有更深入的讨论。

合理的预期

算法交易常被包装成被动收入，现实却并非如此。

  • 优势很小，而且是暂时的。 已公开发表的策略在发表后往往表现变差，而盈利的想法会招来竞争。
  • 回测会美化结果。 即使是诚实的研究者也会发现，由于成本、过拟合和市场变化，实盘结果通常低于回测结果。许多从业者会在心里对回测收益大打折扣。
  • 大多数散户交易者亏钱。 自动化不会改变根本的胜算。对散户日内交易者的研究，例如 Barber、Lee、Liu 和 Odean 针对台湾市场的研究发现，扣除成本后只有极少数人能够持续盈利。
  • 机器人会以新的方式出错。 断线、小数点错位或重复下单，都可能造成任何策略测试都未曾预料到的亏损。2012年的 Knight Capital 事件是经典案例：有缺陷的交易软件让这家公司在不到一小时内亏损了约4.4亿美元。
  • 工作量很大。 数据维护、监控和研究都需要持续投入时间。一个“设置好就不管”的机器人，通常是一个在慢慢亏钱的机器人。

这并不意味着算法交易毫无意义。基于规则的交易能强化纪律，让结果可以度量，并允许在资金承担风险之前进行细致的测试。许多交易者发现，即使从未实现完全自动化，把规则写下来的过程本身也能改善他们的决策。

本分类的其余文章会深入讲解每个环节：研究方面有回测和过拟合；策略类型方面有趋势跟踪、均值回归、配对交易、套利和做市；订单如何进入市场方面有高频交易和执行算法；技术方面有搭建机器人、市场数据和机器学习；对于跟随他人信号而非自建策略的人，还有跟单交易。

常见错误

  • 先写代码，而不是先有想法。 随意组合指标直到回测好看，不过是多走了几步的过拟合。
  • 忽视成本。 用零手续费和完美成交来回测，几乎任何高频想法看起来都能赚钱。
  • 过早上实盘。 跳过模拟交易，意味着要用真金白银去发现 API 和逻辑错误。
  • 过早使用过大仓位。 只有在足够多的交易中实盘结果符合预期之后，才逐步加仓。
  • 没有紧急停止开关。 每个自动化系统都需要对仓位规模和单日亏损设置硬性上限，触及后自动停止交易。
  • 几笔亏损后就放弃或修改规则。 每个策略都有连续亏损的时候。中途修改规则会让之前的测试失去价值。

常见问题

算法交易能赚钱吗？

可以，但大多数散户算法交易者在扣除成本后无法持续盈利。盈利的系统化交易通常依赖真实的经济优势、贴近现实的成本建模和严格的风险控制，而不是自动化本身。

做算法交易需要会编程吗？

会编程帮助非常大，Python 是最常见的入门选择。有些平台提供可视化策略构建器或简单的脚本语言，但会限制你能测试和自动化的内容。

开始算法交易需要多少钱？

做研究和模拟交易完全不需要资金。实盘交易的最低资金取决于市场和券商，但这笔钱应当是你在学习期间即使全部亏光也能承受的金额。

算法交易合法吗？

在大多数主要市场，算法交易是合法的，不过高速交易或代客交易的公司需遵守额外规定，例如欧盟 MiFID II 框架中的算法交易要求。幌骗（spoofing）等操纵行为无论由人还是程序实施都是违法的。

仅供学习参考。本站内容不构成任何金融、投资、法律或税务建议。交易具有很高的亏损风险，杠杆产品的亏损可能超过你投入的本金。规则、费用和平台细节会变化，交易前请向你的券商、交易所或监管机构核实最新条款。
