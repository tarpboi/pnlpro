市场数据（market data）是交易所和其他交易场所产生的价格、报价、成交和订单簿活动的记录。每个算法策略都要两次依赖它：研究和回测需要历史数据，交易需要实时数据。数据的类型、来源、时间戳的标记方式和清洗方式，对策略实测表现的影响可能与策略逻辑本身一样大。

核心要点

  • Tick 数据记录每一笔成交或报价变化；K线数据把活动汇总为一分钟或一天等时间段。
  • Level 1 显示最优买价和卖价，Level 2 显示每个价位的深度，Level 3 显示每一笔订单。
  • 历史数据必须针对拆股、分红和期货换月进行调整，并且应包含已退市的品种。
  • 专业数据需要授权，费用取决于你的身份和使用方式。
  • 时间戳、时区和时钟同步会导致许多回测和实盘交易中不易察觉的错误。

Tick 数据与K线数据

Tick 数据记录每一个单独的事件：每一笔成交（价格、数量、时间，有时还包括主动方向）以及每一次报价更新（买卖价格与挂单量）。它是最详细的数据形式，是日内执行研究、订单流分析和逼真的成交模拟所必需的。它的数据量也很大，存储和处理都更困难。

K线数据把活动汇总为时间段。每根K线记录一个区间（一分钟、一小时或一天）内的开盘价、最高价、最低价、收盘价以及成交量（OHLCV）。K线数据紧凑，足以满足大多数波段和中长线策略的需要。

K线类型 K线如何形成 说明
时间K线 固定时间间隔 最标准，但开盘时与午间所包含的活动量差异很大
Tick K线 固定成交笔数 市场繁忙时K线更多
成交量K线 固定股数或合约数 按活跃程度采样
成交额K线 固定成交金额 在长期历史中可校正价格变化的影响

K线会隐藏信息。日K线不会告诉你最高价出现在最低价之前还是之后，因此如果回测假设止损和止盈在同一天都被触及，就只能去猜哪个先发生。

Level 1、Level 2 和 Level 3

这些术语描述的是一个行情源能显示多少订单簿内容。

级别 内容 典型用途
Level 1 最优买价和卖价（含挂单量）、最新成交价、成交量 大多数散户交易、看图、简单机器人
Level 2（按价位） 买卖双方若干价位上各自的总挂单量 深度分析、执行、短期策略
Level 3（逐笔委托） 每一笔订单，包括新增、修改和撤销 排队位置建模、做市、研究

在美股市场，还要区分汇总行情和直连专有行情：前者把所有交易所的报价合并成全国最佳买卖报价（NBBO），后者由各交易所单独提供，更快也更详细。加密货币交易所通常通过 WebSocket 提供 Level 2 快照和增量更新，有些还提供逐笔委托级别的数据。

按类型划分的历史数据来源

来源类型 提供内容举例 注意事项
直接来自交易所 官方历史成交、报价和订单簿数据 最权威；通常昂贵且复杂
商业数据供应商 经清洗的多资产历史数据、公司行为、基本面数据 质量和覆盖范围参差不齐；要检查幸存者偏差的处理方式
券商和平台 API 其所提供品种的近期K线和 tick 数据 方便；历史可能有限，且因券商而异
加密货币交易所 API 免费的成交、K线，有时还有订单簿快照 宕机期间有数据缺口；各交易所不尽相同
学术数据库 长期、无幸存者偏差的历史数据，如美股的 CRSP 和美国成交与报价数据 TAQ 通常通过大学获取
免费网站 主要资产的日K线 适合学习；要检查复权调整、缺口和已退市品种

做股票研究时，要寻找无幸存者偏差、包含已退市公司和时点准确的指数成分的数据。基本面数据要使用时点数据，即反映每个日期当时已知信息的数据，而不是后来的重述数据。

外汇没有中央交易所，因此散户外汇数据中的“成交量”通常只反映某一家券商或某一个平台的活动。在加密货币领域，一些交易平台报告的成交量历史上曾包含刷量交易，因此要在多个来源之间比较。参见成交量分析。

费用与授权

市场数据是交易所的一项重要业务。要点如下：

  • 订阅者分类。 许多交易所向个人非专业用户收取的费用远低于专业用户。各家定义不同，可能取决于你是否在监管机构注册或是否代他人交易。
  • 展示用途与非展示用途。 交易所通常会对自动化系统使用的数据（非展示用途）与在屏幕上显示的数据分别收费。
  • 再分发。 大多数授权协议禁止把数据转给他人，包括在网站上发布或转售直接由数据衍生的信号。
  • 延迟数据。 延迟约15分钟的数据通常免费或很便宜，但对实盘交易毫无用处。

收费标准会变化，因此请查阅你的券商、供应商或交易所的最新条款。

时间戳与时钟同步

时间是最常见的错误来源之一。

  • 用哪个时间戳？ 一笔成交可能带有交易所的撮合时间、数据发布时间以及你的系统接收时间。在回测中，信号只能使用截至你本应收到数据那一刻的数据。
  • 时区与夏令时。 一律以 UTC 存储。不同国家在不同日期切换夏令时，会使当地交易时段相对于 UTC 发生偏移，从而导致来自多个市场的数据错位。
  • 日K线的定义。 外汇和加密货币全天候交易，因此“日收盘价”取决于数据提供商选择的截止时间。
  • 时钟同步。 实盘系统使用 NTP 同步时钟，通过互联网通常可精确到毫秒以内；或使用 PTP，在合适的网络上可达到微秒级。一些地区的监管机构对交易公司设定了时钟精度要求，对高频交易者的容差最为严格。时钟不同步还会导致交易所 API 拒绝签名请求，如搭建交易机器人中所述。

数据清洗

使用任何数据集之前，都要检查：

  • 错误报价： 远离前后价格的成交记录，通常源于错误或特殊的成交类型。
  • 缺失数据和缺口： 交易所宕机、节假日、停牌。
  • 重复记录和乱序记录。
  • 公司行为： 拆股、合股、分红、分拆和代码变更。
  • 期货换月： 由到期合约拼接而成的连续合约需要一致的调整。
  • 零价格或负价格： 通常是错误，不过某些品种确实曾以负价成交，例如2020年4月的 WTI 原油期货。

过滤规则应当记录在案，并以相同方式应用于研究数据和实时数据。

实例：数据调整

拆股

某股票价格为600美元，随后进行1拆4的拆股，每股变为四股，股价变为约150美元。在未调整的数据中，这个序列看起来一夜之间暴跌75%。回测会把它当作崩盘，触发根本不存在的止损和均值回归买入信号。

经拆股调整的数据会把拆股前的所有价格除以4（成交量乘以4），于是拆股前的600变为150，序列保持连续。

期货换月

一位交易者用季度期货构建连续序列。在换月日，即将到期的合约交易价为4,000，下一个合约为4,020。不做调整直接拼接会产生一个虚假的20点跳空。后复权（back-adjusted）序列会给之前的每个价格都加上20点，从而消除跳空。另一种方法是比例调整，即把之前的价格乘以4,020 / 4,000 = 1.005，它能保持百分比收益不变。

数据量

单只美股在常规交易时段（每天390分钟）内的一分钟K线，按252个交易日计算，每年产生390 × 252 = 98,280根K线，存储起来很容易。而同一只股票的 tick 和报价数据，对于交易活跃的品种每天可能多达数百万条记录，这就是 tick 级研究需要合适的存储和工具的原因。

常见错误

  • 用未调整的价格做股票回测。
  • 只使用当前上市的代码，这会把幸存者偏差带进结果。
  • 混用不同数据源的时区。
  • 以为日收盘价放之四海而皆准，而忽视了24小时交易的市场。
  • 对需要 tick 级成交模拟的策略用K线数据回测。
  • 分享或发布数据时忽视授权条款。

常见问题

Level 1 和 Level 2 数据有什么区别？

Level 1 只显示最优买价、最优卖价和最新成交价。Level 2 显示订单簿买卖双方若干价位上的可成交数量，能让你看到市场深度。

在哪里可以获得历史行情数据？

来源包括交易所、商业数据供应商、券商和平台 API、加密货币交易所 API 以及学术数据库。免费来源适合学习，但在依赖它们之前，要检查复权调整、缺口和幸存者偏差。

回测需要 tick 数据吗？

对大多数日线或波段策略来说不需要，干净的K线数据就足够了。对于日内策略、逼真的成交与滑点建模，以及任何依赖订单簿的策略，tick 或报价数据才是关键。

市场数据为什么这么贵？

交易所和供应商对数据的采集、分发和授权收费，而专业用途和自动化用途通常更贵。个人非专业用户往往可以通过券商以便宜得多的价格获得实时数据。
