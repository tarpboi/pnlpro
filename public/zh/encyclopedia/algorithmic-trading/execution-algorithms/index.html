执行算法（execution algorithms）是把大额订单拆成小单、随时间逐步发往市场的程序，目标是以较好的平均价格买入或卖出，同时不过度推动市场。它们回答的是“该怎么交易”，而不是“该交易什么”。即使是拥有真实优势的策略，也可能因执行糟糕而亏钱，所以无论规模大小，这对任何系统化交易者都是一个重要课题。

核心要点

  • 大额订单会推动价格；分时拆单可以降低市场冲击，但会增加暴露于价格漂移的风险。
  • TWAP 把订单在时间上均匀分布，VWAP 跟随典型的成交量模式，POV 按实时成交量的固定比例交易。
  • 执行差额算法在市场冲击与等待期间价格跑开的风险之间取得平衡。
  • 智能订单路由把每一笔子单发往价格和流动性最好的交易场所。
  • 衡量执行质量时，要以你决定交易那一刻的价格为基准，而不只是对比当天的平均价格。

执行为何重要

每笔交易除了佣金之外，还要支付其他成本：

  • 点差： 相对于中间价，从买价跨到卖价，每一边都要付出买卖价差的一半。
  • 市场冲击： 大额订单会消耗可用流动性并推动价格。其中一部分波动是暂时的，停止交易后会恢复；另一部分是永久的，因为你的交易泄露了信息。
  • 时机风险： 如果为了降低冲击而慢慢交易，价格可能会因为不相关的原因离你而去。

执行设计就是在冲击（慢慢交易）与时机风险（快速交易）之间权衡。经典的形式化处理是2000年前后提出的 Almgren-Chriss 框架，它求解的交易计划使预期成本加上对成本不确定性的惩罚项最小。

一条被广泛引用的经验法则——平方根定律——认为，市场冲击大致随订单规模相对于日成交量的平方根增长：

冲击 ≈ c × 日波动率 × √(订单规模 / 日均成交量)

其中 c 是一个常数，通常估计在1左右。应将其视为粗略参考，而非精确预测。

主要算法类型

算法 交易方式 优点 缺点
TWAP（时间加权平均价格） 在设定时段内按固定间隔等量拆单 简单、可预测、容易实现 忽略成交量模式；规律的拆单可能被识别
VWAP（成交量加权平均价格） 按历史日内成交量曲线确定每笔子单规模 流动性高时多交易；匹配常用基准 依赖历史成交量；仍是固定计划
POV（成交量百分比） 按实时市场成交量的固定比例（如10%）交易 适应实际流动性 完成时间不确定；可能追逐成交量突增
执行差额（到达价格） 开始时交易较快，根据紧迫性和风险进行调整 使相对于决策价格的成本最小 更复杂；前期冲击更大
寻找流动性 在明盘和暗盘场所寻找大单流动性，通常伺机而动 适合流动性差的品种 有信息泄露风险

TWAP

TWAP 把订单分成等量的若干份，按固定间隔发出，例如每五分钟1,000股。许多加密货币交易所直接提供 TWAP 订单。好的实现会对子单规模和时间做轻微随机化，使其他交易者难以识别其规律。

import random

def twap_schedule(total_qty, start_ts, end_ts, n_slices, jitter=0.2):
    """把 total_qty 拆成 n_slices 份，均匀分布在两个时间戳（秒）之间。"""
    step = (end_ts - start_ts) / n_slices
    base, remainder = divmod(total_qty, n_slices)
    schedule = []
    for i in range(n_slices):
        qty = base + (1 if i < remainder else 0)
        offset = random.uniform(0.0, jitter) * step   # 避免完全规律的模式
        schedule.append((start_ts + i * step + offset, qty))
    return schedule

VWAP

在大多数股票市场中，日内成交量呈 U 形分布：开盘和收盘时成交密集，午间较为清淡。VWAP 算法利用历史成交量分布，在市场最活跃时多交易。成交量加权平均价格本身（详见VWAP）也是评判成交质量最常用的基准。

POV

POV 或参与率算法会观察实时成交量，并按设定比例参与交易。如果市场一分钟内成交50,000股、参与率为10%，算法的目标就是交易5,000股。它能适应真实的市场状况，但无法保证订单何时完成。

执行差额

执行差额（implementation shortfall）的概念由 André Perold 于1988年提出，衡量的是以决策价格即时成交的纸面组合收益与实际取得的收益之间的差距。执行差额算法试图最小化这一差距，通常的做法是在前期更积极地交易，以减少暴露于价格漂移的时间。

智能订单路由

许多市场分散在多家交易所和另类交易场所。智能订单路由（SOR）会检查各场所的价格和可成交数量，在考虑费用、返佣、成交概率和延迟后，把每一笔子单发往最佳场所。在加密货币领域，聚合器在各交易所或 DEX 流动性池之间发挥类似作用。在美国，Regulation NMS 等规则要求券商不得以劣于其他交易所展示的更优价格成交；其他地区也有各自的最佳执行规则。

衡量滑点

不衡量，就无法改进执行。常用基准：

基准 定义 说明
到达价格 订单发出时的中间价 衡量总执行成本最诚实的指标
决策价格 策略产生信号时的价格 能捕捉从信号到下单之间的延迟
区间 VWAP 订单存续期间的市场 VWAP 很流行，但只要顺着有利方向交易就能“跑赢”它
收盘价 官方收盘价 适用于以收盘价为基准的策略

成本通常以基点（bps）表示，1 bp = 0.01%。对于买单，滑点 = (平均成交价 − 基准价) / 基准价。对于卖单，符号相反。

实例：执行差额

某策略在价格为50.00美元时决定买入10,000股。纸面组合价值为10,000 × 50.00 = 500,000美元。

  • 算法以平均50.12美元买入了8,000股。剩余的2,000股在价格涨到50.60美元之前未能成交，订单被撤销。
  • 执行成本：8,000 × (50.12 − 50.00) = 960美元。
  • 未成交股份的机会成本：2,000 × (50.60 − 50.00) = 1,200美元。
  • 佣金：40美元。
  • 总执行差额：960 + 1,200 + 40 = 2,200美元，即2,200 / 500,000 = 0.44%（44 bps）。

如果只看成交的8,000股，这笔订单看起来执行得不错，但错过剩余股份的代价比滑点本身还大。

估算市场冲击

某股票日波动率为2%，日均成交量为1,000,000股。一笔10,000股的订单相当于日成交量的1%。取 c = 1，平方根法则给出的冲击约为2% × √0.01 = 2% × 0.1 = 0.2%，即20 bps。把订单扩大四倍到40,000股，估计冲击只翻一倍，约为40 bps，因为 √0.04 = 0.2。

散户与系统化交易者的执行

散户订单相对于市场成交量通常很小，因此在流动性好的市场中冲击很小。但执行仍然重要：

  • 在合适的场合用限价单代替市价单；订单类型一文解释了各种选择。
  • 避免在开盘和收盘的最初与最后几分钟以及重大消息前后交易，那时点差会扩大。
  • 在小盘股、山寨币或事件合约等清淡市场中，几千美元就可能推动价格；拆单会有帮助。
  • 在每一步记录信号时间、下单时间、成交价和中间价，再把实盘成本与回测假设进行比较。参见交易成本与费用。

常见错误

  • 只以 VWAP 为基准衡量。 它可能掩盖延迟和未成交的成本。
  • 忽视未成交订单。 在盈利品种上错过的交易，是一种真实且往往很大的成本。
  • 可预测的拆单。 相同间隔、相同规模的子单可能被识别并被针对性交易。
  • 在薄订单簿中使用市价单。 一笔订单就可能连吃好几档价格。
  • 假设回测成交等于实盘成交。 始终要把真实执行与假设进行核对。

常见问题

TWAP 和 VWAP 有什么区别？

TWAP 把订单在时间上均匀分布，而 VWAP 根据一天中该时段的典型成交量确定每笔子单的规模。VWAP 通常在开盘和收盘附近交易得更多，因为股票市场的大部分成交量都发生在这些时段。

什么是执行差额？

它是以决策价格即时成交的理想交易结果与实际结果之间的差距，包括滑点、费用以及未能成交部分的成本。它被认为是最全面的交易成本衡量指标之一。

散户需要执行算法吗？

大多数散户订单足够小，在流动性好的市场中用简单的限价单就够了。拆单、避开剧烈波动时段等执行技巧，在清淡市场中以及对交易频繁的策略而言更为重要。

什么是智能订单路由？

智能订单路由是一种软件，它把每一笔订单或订单的每一部分，发往在价格、数量、费用和成交可能性方面综合最优的交易场所。
