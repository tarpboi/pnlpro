トレード戦略のバックテストのやり方

バックテストとは、一連の売買ルールを過去データに当てはめ、その戦略がどのような成績を上げていたかを推定するプロセスです。アルゴリズム取引における主要なリサーチツールであると同時に、最も自分を欺きやすい場所でもあります。丁寧なバックテストはデータ、コスト、タイミングを現実的にモデル化します。いい加減なバックテストは見栄えのする数字を生み出しますが、その数字は実際のお金を投じた瞬間に消えてしまいます。

要点

  • バックテストの質はデータの質で決まります。最も深刻な誤りは、生存者バイアスと先読みバイアス（ルックアヘッドバイアス）の2つです。
  • 手数料、スプレッド、スリッページは保守的に見積もってください。戦略がそもそも利益を出せるかどうかは、コストで決まることが多いからです。
  • 戦略が一度も見ていないデータをアウトオブサンプル検証用に取っておき、定期的な再調整が必要な戦略にはウォークフォワード分析を使ってください。
  • 戦略は複数の指標を組み合わせて評価します。シャープレシオ、ソルティノレシオ、最大ドローダウン、プロフィットファクター、取引回数です。
  • 良いバックテストは確信を高めますが、将来の結果を保証することは決してありません。

バックテストの仕組み

最も単純な形では、バックテストは過去のデータを1本ずつ（バーごとに）進めていきます。各ステップで、その時点で入手できた情報だけを使ってルールが何をしたかを問い、模擬的な注文と約定を記録し、口座の資産額を追跡します。

一般的な設計は2つあります。

設計 仕組み 長所 短所
ベクトル化型 配列演算でシリーズ全体のシグナルとリターンを一度に計算する 非常に高速で、初期のリサーチに向く 先読みバイアスが入り込みやすい。注文の約定、ストップ、ポジション制限をモデル化しにくい
イベント駆動型 実運用のシステムと同じように、各バーや各ティックをイベントとして処理する 注文処理が現実的。コードを実運用に流用できることが多い 速度が遅く、構築の手間がかかる

多くのリサーチャーは、ベクトル化型のテストでアイデアをふるいにかけ、有望なものをイベント駆動型のシミュレーターで確認しています。

データの品質

不正確なデータは、自信に満ちていながら無意味な結果を生みます。少なくとも次の点を確認してください。詳しくはマーケットデータの記事を参照してください。

  • コーポレートアクション。 株価は株式分割と配当に合わせて調整しなければなりません。そうしないと、バックテストは存在しない暴落を検出し、配当収入を取りこぼします。
  • 先物のロール。 連続先物のシリーズは、限月の満期をまたいで一貫した方法でつなぎ合わせる必要があります。
  • 異常ティックと欠損。 誤った約定記録、欠けたバー、重複したレコードは偽のシグナルを生みます。
  • タイムゾーンとタイムスタンプ。 取引所時間、現地時間、UTC が混在すると、シグナルが何時間もずれることがあります。
  • バーの作り方。 データベンダーによって日足の終値の時刻が異なることがあり、24時間取引されるFXや暗号資産では特にそうです。

バックテストを台無しにするバイアス

生存者バイアス

生存者バイアスは、検証対象のユニバースに現在も存在する資産しか含まれていない場合に生じます。倒産した企業、上場廃止になった企業、買収された企業は、多くの無料データセットから消えています。現在の指数構成銘柄だけで検証した戦略は勝者だけで検証されていることになり、リターンが水増しされます。値下がりした銘柄を買う戦略では特にそうです。暗号資産でも同じ問題があり、崩壊した何千ものトークンが現在の銘柄リストから抜け落ちています。対策は、消滅した銘柄を含み、各時点の指数構成銘柄（ポイント・イン・タイム）を反映した、生存者バイアスのないデータセットを使うことです。

先読みバイアス

先読みバイアスとは、取引の時点では入手できなかったはずの情報を使ってしまうことです。よくある例は次のとおりです。

  • その日の終値を使ってシグナルを生成し、同時にその同じ終値で買えたと仮定する。
  • 財務諸表のデータを、実際に公表された日ではなく期末日の時点で使う。
  • 将来の部分を含むサンプル全体から計算した統計量（平均、最大値）でデータを正規化する。
  • トレーダーが実際に目にした速報値ではなく、改定後の経済指標データを使う。

便利な習慣は、すべてのシグナルを1バー先にずらし、バー t で計算したシグナルはバー t+1 より前には取引しないようにすることです。

その他のバイアス

  • 選択バイアス： 上昇したことがすでにわかっている市場だけで検証すること。
  • データスヌーピング： 多数のバリエーションを試し、最も良かったものを報告すること。これについてはオーバーフィッティングとデータスヌーピングで解説しています。
  • 流動性バイアス： 薄い市場でも気配値どおりの価格で大きなサイズを取引できたと仮定すること。

コストとスリッページのモデル化

模擬取引の一つひとつに、現実的なコストを負担させるべきです。

  • 売買手数料と取引所手数料。 暗号資産取引所のメイカー・テイカー手数料も含みます。
  • スプレッド。 アスクで買ってビッドで売ると、往復ごとにビッド・アスク・スプレッドの全額がコストになります。
  • スリッページとマーケットインパクト。 成行注文やストップ注文は、特に値動きの速い相場やサイズが大きい場合、直近の価格より不利な価格で約定することがよくあります。
  • 資金調達コスト。 オーバーナイトのスワップ、無期限先物のファンディングの支払い、空売りの貸株料です。

賢明な方法は、可能であれば実際の約定からコストを見積もり、そのうえでコストを2倍にしてもう一度バックテストを実行することです。楽観的なコスト水準でしか機能しない戦略は、おそらく機能しません。

インサンプル、アウトオブサンプル、ウォークフォワード

始める前に過去データを分割しておきます。インサンプル部分で戦略を構築・調整し、アウトオブサンプル部分で一度だけ検証します。ルールを微調整するためにアウトオブサンプルのデータに何度も戻ると、それはもはやアウトオブサンプルではなくなります。

ウォークフォワード分析は、このプロセスを時間軸に沿って繰り返します。たとえば、2015年から2018年でパラメーターを最適化して2019年で検証し、2016年から2019年で最適化して2020年で検証する、という具合です。検証期間をつなぎ合わせると、戦略がリアルタイムで再調整されていた場合の姿を反映した、アウトオブサンプルの資産曲線が得られます。インサンプルとウォークフォワードの結果に大きな差がある場合は、オーバーフィッティングが疑われます。

パフォーマンス指標

戦略を1つの数字で表すことはできません。複数の指標を組み合わせて使ってください。

指標 計算式 わかること
CAGR (Ending equity / Starting equity)^(1 / years) − 1 年平均成長率（複利）
シャープレシオ Mean(R − Rf) / StdDev(R − Rf)。√(1年あたりの期間数) を掛けて年率換算 全体のボラティリティ1単位あたりのリターン
ソルティノレシオ (Mean(R) − T) / 下方偏差。同じ方法で年率換算 下方ボラティリティだけを対象にした1単位あたりのリターン
最大ドローダウン 資産額のピークから底までの最大の下落幅を、ピークに対する割合で表したもの 過去最悪の苦しさ
プロフィットファクター 総利益 / 総損失（絶対値） 1ドルの損失に対して何ドル稼いだか
勝率と期待値 勝ちトレードの割合、1回あたりの平均損益 リターンがどのように分布しているか

ここで R は1期間あたりの戦略リターン、Rf は1期間あたりの無リスク金利、T は目標リターン（多くの場合ゼロ）です。下方偏差は、全期間にわたって min(0, R − T)² の平均を取った値の平方根で、目標を上回った期間はゼロとして数えます。日次データでは、日次の比率に √252、約15.87を掛けます。ドローダウンと回復の計算についてはドローダウンと破産リスクで、期待値についてはリスクリワードと期待値で解説しています。

以下の関数は、リターンの系列、資産曲線、トレード結果のリストからこれらの指標を計算します。

import numpy as np

def sharpe(returns, rf_per_period=0.0, periods_per_year=252):
    excess = np.asarray(returns) - rf_per_period
    return np.sqrt(periods_per_year) * excess.mean() / excess.std(ddof=1)

def sortino(returns, target=0.0, periods_per_year=252):
    r = np.asarray(returns)
    downside = np.minimum(r - target, 0.0)
    downside_dev = np.sqrt(np.mean(downside ** 2))
    return np.sqrt(periods_per_year) * (r.mean() - target) / downside_dev

def max_drawdown(equity):
    equity = np.asarray(equity, dtype=float)
    peaks = np.maximum.accumulate(equity)
    return ((peaks - equity) / peaks).max()

def profit_factor(trade_pnls):
    pnl = np.asarray(trade_pnls, dtype=float)
    gross_loss = -pnl[pnl < 0].sum()
    return pnl[pnl > 0].sum() / gross_loss if gross_loss > 0 else np.inf

計算例

ある戦略が10,000ドルから始まり、次のような結果（単位はドル）で10回取引したとします：+300、−200、+150、−100、−250、+400、−150、+200、−300、+250。

  • 総利益： 300 + 150 + 400 + 200 + 250 = 1,300。
  • 総損失： 200 + 100 + 250 + 150 + 300 = 1,000。
  • プロフィットファクター： 1,300 / 1,000 = 1.30。
  • 純利益： 300ドル。したがって期待値は1回あたり30ドルで、勝率は50%です。
  • 資産額の推移： 10,300、10,100、10,250、10,150、9,900、10,300、10,150、10,350、10,050、10,300。
  • 最大ドローダウン： ピークの10,300から底の9,900まで、400 / 10,300 ≈ 3.9% の下落です。

リスク調整後の比率については、より長期の検証で、日次平均リターン0.05%、日次標準偏差1.0%、下方偏差0.7%、無リスク金利ゼロという結果が得られたとします。年率換算したシャープレシオは 0.05 / 1.0 × 15.87 ≈ 0.79、ソルティノレシオは 0.05 / 0.7 × 15.87 ≈ 1.13 です。

10回の取引では、これらの数字のどれも信頼するには少なすぎます。おおまかな目安として、多くのリサーチャーは、統計を意味のあるものとして扱う前に、さまざまな相場環境にまたがる少なくとも数百回の取引を求めます。

よくある間違い

  • シグナルを生成したバーで取引する。 終値から計算したシグナルを、その同じ終値で約定させることはできません。
  • 現在の指数構成銘柄を使う。 すべての結果に生存者バイアスが組み込まれてしまいます。
  • コストをゼロまたはごくわずかと仮定する。 回転率の高い戦略は特に影響を受けやすいです。
  • アウトオブサンプルのデータを再利用する。 一度のぞくたびに、それはインサンプルのデータに変わります。
  • 取引回数が少なすぎる。 ほんの数回の大勝ちだけで、見事だが無意味なバックテストができあがることがあります。
  • キャパシティを無視する。 1,000ドルでは機能する戦略が、注文で価格が動いてしまうために100,000ドルでは失敗することがあります。

よくある質問

バックテストで良いシャープレシオはどのくらいですか？

多くの実務家は、単一の戦略であれば年率換算のシャープレシオが1を超えると有望と見なします。日次の戦略で3を超えるような極端に高いバックテスト値は、本物のエッジよりも、エラー、先読みバイアス、オーバーフィッティングを示していることのほうが多いです。

バックテストにはどのくらいの過去データが必要ですか？

上昇相場、下落相場、横ばい相場、そして少なくとも1回のストレス期間など、さまざまな相場局面を含むのに十分な量が必要です。日次の戦略なら10年以上になることが多く、日中の戦略なら取引回数が多ければもっと短い年数で足りることもあります。

バックテストとペーパートレードの違いは何ですか？

バックテストは過去データを再生するもので、ペーパートレードは実際のお金を使わずにリアルタイムの価格で戦略を動かすものです。ペーパートレードでは、バックテストでは発見できない執行面やソフトウェアの問題を見つけられます。

実運用の結果がバックテストと異なるのはなぜですか？

よくある原因は、コストとスリッページの過小評価、過去のノイズへのオーバーフィッティング、データのバイアス、市場の振る舞いの変化です。ある程度の差は普通ですが、大きな差がある場合はバックテストに欠陥があったということです。

教育目的のコンテンツです。本サイトの内容は、金融・投資・法律・税務に関する助言ではありません。トレードには大きな損失リスクがあり、レバレッジ商品では入金額を超える損失が生じることがあります。ルール、手数料、プラットフォームの条件は変わります。取引の前に、ご利用の証券会社、取引所、規制当局で最新の条件をご確認ください。
