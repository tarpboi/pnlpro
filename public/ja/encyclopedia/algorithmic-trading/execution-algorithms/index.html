執行アルゴリズムとは、大口の注文を小さく分割し、時間をかけて市場に送るプログラムのことで、市場を大きく動かすことなく良い平均価格で売買することを目指します。執行アルゴリズムが答えるのは「何を取引すべきか」ではなく「どのように取引すべきか」という問いです。本物のエッジを持つ戦略でも、執行がまずければお金を失うことがあります。そのため、規模の大小を問わず、あらゆるシステムトレーダーにとって重要なテーマです。

要点

  • 大口注文は価格を動かします。時間をかけて分割すればマーケットインパクトは減りますが、価格がずれていくリスクにさらされる時間は長くなります。
  • TWAP は注文を時間に対して均等に分散し、VWAP は典型的な出来高パターンに従い、POV はリアルタイムの出来高の一定割合を取引します。
  • インプリメンテーション・ショートフォール型のアルゴリズムは、インパクトと、待っている間に価格が離れていくリスクとのバランスを取ります。
  • スマートオーダールーティングは、分割した注文の一つひとつを、その時点で最も価格と流動性の良い取引所に送ります。
  • 執行の質は、その日の平均価格だけでなく、取引を決めた瞬間の価格と比較して測定してください。

執行が重要な理由

すべての取引には、売買手数料以外にもコストがかかります。

  • スプレッド： ビッドからアスクへとスプレッドをまたぐと、仲値と比べて片道ごとにビッド・アスク・スプレッドの半分がコストになります。
  • マーケットインパクト： 大口注文は利用可能な流動性を食いつぶし、価格を押し動かします。その動きの一部は一時的なもので、取引をやめれば戻ります。一部は恒久的なもので、自分の取引が情報を明らかにしてしまうためです。
  • タイミングリスク： インパクトを減らそうとゆっくり取引すると、無関係な理由で価格が不利な方向に離れていくことがあります。

執行の設計とは、インパクト（ゆっくり取引する）とタイミングリスク（素早く取引する）とのトレードオフです。古典的な理論的枠組みは、2000年頃に発表された Almgren-Chriss モデルで、期待コストにコストの不確実性に対するペナルティを加えたものを最小化する取引スケジュールを求めます。

広く引用される経験則である「平方根の法則」によれば、インパクトは1日の出来高に対する注文サイズの平方根におおよそ比例して大きくなります。

Impact ≈ c × daily volatility × √(order size / average daily volume)

ここで c は定数で、通常は1前後と推定されます。精密な予測ではなく、おおまかな目安として扱ってください。

主なアルゴリズムの種類

アルゴリズム 取引の仕方 長所 短所
TWAP（時間加重平均価格） 一定期間にわたり、等間隔で均等な量に分けて取引する シンプルで予測しやすく、構築が容易 出来高のパターンを無視する。規則的な分割は見破られることがある
VWAP（出来高加重平均価格） 過去の日中出来高カーブに合わせたサイズで分割する 流動性が高いときに多く取引する。一般的なベンチマークに合致する 過去の出来高に依存する。スケジュールは固定のまま
POV（出来高参加率） リアルタイムの市場出来高の一定割合（たとえば10%）を取引する 実際の流動性に適応する 完了時刻がわからない。出来高の急増を追いかけてしまうことがある
インプリメンテーション・ショートフォール（到着価格） 最初は速めに取引し、緊急性とリスクに応じて調整する 意思決定時の価格に対するコストを最小化する より複雑。初期のインパクトが大きくなる
流動性探索型 公開市場と非公開の取引の場の両方で、多くは機会を見計らってまとまった数量を探す 流動性の低い銘柄に向く 情報漏洩のリスク

TWAP

TWAP は注文を均等な量に分け、たとえば5分ごとに1,000株というように一定間隔で送ります。多くの暗号資産取引所が TWAP 注文を直接提供しています。優れた実装では、他のトレーダーにパターンを簡単に見破られないよう、分割サイズとタイミングをわずかにランダム化します。

import random

def twap_schedule(total_qty, start_ts, end_ts, n_slices, jitter=0.2):
    """total_qty を n_slices 個に分け、2つのタイムスタンプ（秒）の間に均等に配置する。"""
    step = (end_ts - start_ts) / n_slices
    base, remainder = divmod(total_qty, n_slices)
    schedule = []
    for i in range(n_slices):
        qty = base + (1 if i < remainder else 0)
        offset = random.uniform(0.0, jitter) * step   # 完全に規則的なパターンを避ける
        schedule.append((start_ts + i * step + offset, qty))
    return schedule

VWAP

ほとんどの株式市場では、1日の出来高はU字型を描きます。寄り付きと大引けに多く、昼頃に少なくなります。VWAP アルゴリズムは過去の出来高プロファイルを使い、市場が最も活発なときに多く取引します。出来高加重平均価格そのもの（VWAPで解説）は、約定の良し悪しを判断する最も一般的なベンチマークでもあります。

POV

POV（参加率）アルゴリズムはリアルタイムの出来高を監視し、その一定割合を取引します。市場で1分間に50,000株が取引され、参加率が10%なら、アルゴリズムは5,000株の取引を目指します。実際の状況に適応しますが、注文がいつ完了するかは約束できません。

インプリメンテーション・ショートフォール

インプリメンテーション・ショートフォールの概念は、1988年に André Perold が提唱したもので、意思決定時の価格で即座に取引したと仮定したペーパーポートフォリオのリターンと、実際に達成したリターンとの差を測定します。ショートフォール型のアルゴリズムは、通常、序盤により積極的に取引して価格のずれにさらされる時間を減らすことで、その差を最小化しようとします。

スマートオーダールーティング

多くの市場は、複数の取引所や代替的な取引の場に分散しています。スマートオーダールーター（SOR）は、各取引の場の価格と利用可能な数量を確認し、手数料、リベート、約定確率、レイテンシーを考慮したうえで、分割された子注文をそれぞれ最適な場所に送ります。暗号資産では、アグリゲーターが取引所や DEX の流動性プールをまたいで同様の役割を果たしています。米国では、Regulation NMS などのルールにより、ブローカーは他の取引所で表示されているより良い価格を飛ばして取引することを避けなければなりません。他の地域にもそれぞれ最良執行のルールがあります。

スリッページの測定

測定していない執行を改善することはできません。一般的なベンチマークは次のとおりです。

ベンチマーク 定義 備考
到着価格 注文を送った時点の仲値 執行コスト全体を最も正直に測る指標
意思決定価格 戦略がシグナルを生成した時点の価格 シグナルから注文までの遅延を捉える
期間 VWAP 注文が出ていた期間中の市場の VWAP 人気があるが、単に有利な方向に取引するだけで「勝てて」しまうことがある
終値 公式の終値 終値をベンチマークとする戦略に関係する

コストは通常ベーシスポイント（bps）で表し、1 bp = 0.01% です。買い注文の場合、スリッページ = (平均約定価格 − ベンチマーク) / ベンチマーク。売り注文の場合は符号を逆にします。

計算例：インプリメンテーション・ショートフォール

ある戦略が、価格が50.00ドルのときに10,000株を買うと決定しました。ペーパーポートフォリオの価値は 10,000 × 50.00 = 500,000ドルです。

  • アルゴリズムは8,000株を平均50.12ドルで買いました。残りの2,000株は、価格が50.60ドルまで上昇する前に約定せず、注文は取り消されました。
  • 執行コスト：8,000 × (50.12 − 50.00) = 960ドル。
  • 未約定株式の機会費用：2,000 × (50.60 − 50.00) = 1,200ドル。
  • 売買手数料：40ドル。
  • ショートフォールの合計：960 + 1,200 + 40 = 2,200ドル、つまり 2,200 / 500,000 = 0.44%（44 bps）。

約定した8,000株だけで判断すれば、この注文はうまく執行されたように見えました。しかし、残りの株を買い損ねたことのコストは、スリッページそのものより大きかったのです。

インパクトの推定

ある株式の日次ボラティリティが2%、1日の平均出来高が1,000,000株だとします。10,000株の注文は1日の出来高の1%です。c = 1 とした平方根の法則では、インパクトは約 2% × √0.01 = 2% × 0.1 = 0.2%、つまり20 bps と推定されます。注文を4倍の40,000株にしても、√0.04 = 0.2 なので、推定インパクトは2倍の約40 bps にしかなりません。

個人トレーダーとシステムトレーダーにとっての執行

個人の注文は通常、市場の出来高に比べて小さいため、流動性の高い市場ではインパクトはわずかです。それでも執行は重要です。

  • 適切な場面では成行注文ではなく指値注文を使いましょう。選択肢については注文の種類で説明しています。
  • スプレッドが広がる取引時間の最初と最後の数分間や、重要なニュースの前後での取引は避けましょう。
  • 小型株、アルトコイン、イベント契約などの薄い市場では、数千ドルで価格が動くことがあります。注文を分割すると効果があります。
  • 各段階でシグナルの時刻、注文の時刻、約定価格、仲値をログに記録し、実運用のコストをバックテストの想定と比較しましょう。取引コストと手数料を参照してください。

よくある間違い

  • VWAP だけを基準に測定する。 遅延や約定しなかった注文のコストが隠れてしまうことがあります。
  • 未約定の注文を無視する。 上昇した銘柄を買い損ねることは、現実の、しかもしばしば大きなコストです。
  • 予測可能な分割。 同じサイズを同じ間隔で出すと見破られ、逆手に取られることがあります。
  • 薄い板で成行注文を使う。 1つの注文で複数の価格帯を食い上がってしまうことがあります。
  • バックテストの約定が実運用の約定と同じだと思い込む。 実際の執行を常に想定と照合してください。

よくある質問

TWAP と VWAP の違いは何ですか？

TWAP は注文を時間に対して均等に分散させ、VWAP はその時間帯の典型的な出来高に応じて各分割のサイズを決めます。VWAP は通常、株式市場の出来高の大半が集中する寄り付きと大引けの近くで多く取引します。

インプリメンテーション・ショートフォールとは何ですか？

意思決定時の価格で即座に執行された理想的な取引の結果と、実際の結果との差のことで、スリッページ、手数料、そして最後まで約定しなかった株式のコストを含みます。取引コストを最も網羅的に測る指標の一つとされています。

個人トレーダーに執行アルゴリズムは必要ですか？

個人の注文の多くは十分に小さいため、流動性の高い市場では単純な指値注文で問題ありません。注文の分割や値動きの激しい時間帯を避けるといった執行の工夫は、薄い市場や、頻繁に取引する戦略を使うトレーダーにとってより重要になります。

スマートオーダールーティングとは何ですか？

スマートオーダールーティングとは、注文、または分割された注文の一つひとつを、価格、数量、手数料、約定の可能性の組み合わせが最も良い取引の場に送るソフトウェアです。

教育目的のコンテンツです。本サイトの内容は、金融・投資・法律・税務に関する助言ではありません。トレードには大きな損失リスクがあり、レバレッジ商品では入金額を超える損失が生じることがあります。ルール、手数料、プラットフォームの条件は変わります。取引の前に、ご利用の証券会社、取引所、規制当局で最新の条件をご確認ください。
