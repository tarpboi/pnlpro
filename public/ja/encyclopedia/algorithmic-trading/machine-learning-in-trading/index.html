トレードにおける機械学習

トレードにおける機械学習（ML）とは、アルゴリズム取引の一分野で、人間が書いたルールに従うのではなく、データからパターンを学習するアルゴリズムを使って、価格を予測したり、相場環境を分類したり、ニュースなどのテキストを処理したりするものです。クオンツファンドで広く使われていますが、金融データはノイズが多く絶えず変化しているため、機械学習モデルは存在しないパターンを見つけてしまいやすいという特有の弱点があります。慎重に使えば機械学習は役に立つツールですが、不用意に使えば、説得力があるのに実運用では失敗するバックテストを作る最短の方法の一つになります。

要点

  • トレードにおける機械学習の大半は教師あり学習で、現時点でわかっている特徴量から将来のリターンや方向を予測するものです。
  • どのアルゴリズムを選ぶかより、ラベルの定義とモデルの検証方法のほうが重要です。
  • 市場は非定常で、シグナル対ノイズ比（S/N比）が非常に低いため、わずかな精度の向上でも意味を持ちうる一方、大幅な向上は疑ってかかるべきです。
  • 標準的な交差検証は時系列データで将来の情報を漏らしてしまいます。ウォークフォワード検証やパージング付きの検証を使ってください。
  • 大規模言語モデル（LLM）はテキストの読解や分類に役立ちますが、LLM を使ったバックテストは、検証日以降の出来事についての知識に汚染されている可能性があります。

機械学習にできること、できないこと

機械学習は、多数の弱いシグナルを組み合わせること、非線形な関係を捉えること、そして何千ものニュース記事や開示書類など、人間が大量には読みきれないデータを処理することを得意としています。データの中に存在しない予測可能性を生み出すことはできません。資産価格は、ほとんどの時間軸でおおむね予測不可能であり、存在する予測可能性の多くも競争によって消えていきます。よく知られた2020年の研究で、Gu、Kelly、Xiu は、ツリーのアンサンブルやニューラルネットワークといった柔軟な手法が、従来の線形モデルよりも米国株の月次リターンをうまく予測することを示しましたが、リターンのうち予測可能な部分はわずかでした。

シグナルのための教師あり学習

問題の種類

  • 回帰： 5日間のリターンなど、次のリターンの大きさを予測します。
  • 分類： 上昇か下落か、あるいは「ストップより先に利益目標に到達するか」といったカテゴリーを予測します。
  • ランキング： 期待リターンの順に資産を並べ、上位を買い、下位を空売りします。クロスセクションの銘柄選択でよく使われる方法です。

代表的なモデル

モデルの系統 長所 短所
線形回帰と正則化回帰（リッジ、ラッソ） シンプルで安定しており、解釈しやすい 非線形の効果を捉えられない
ツリーのアンサンブル（ランダムフォレスト、勾配ブースティング） 非線形性や種類の混在した特徴量をうまく扱える。表形式データに強い ノイズに過学習することがある。予測が滑らかでない
ニューラルネットワーク 柔軟。系列データ、テキスト、画像を扱える 大量のデータが必要。解釈しにくい。最も過学習しやすい

一般的な表形式のトレードデータでは、正則化線形モデルと勾配ブースティング木がよく使われる出発点です。より複雑なモデルを正当化するには、より多くのデータが必要です。

特徴量

特徴量とは、モデルが使う入力のことです。予測を行う時点でわかっているものでなければなりません。

  • 価格ベース： 複数の期間にわたる過去のリターン、ボラティリティ、移動平均線からの乖離、RSIなどのテクニカル指標。
  • 出来高と注文フロー： 相対出来高、板の不均衡、約定の方向。
  • クロスセクション： セクターや市場全体に対する資産の相対リターン。
  • ファンダメンタル： バリュエーション指標、決算サプライズ。データは公表日以降のものだけを使います。
  • オルタナティブデータ： テキストのセンチメント、Webトラフィック、衛星データや決済データ。
  • 市場環境： ボラティリティ指数、金利、資金調達率（ファンディングレート）などのセンチメント指標。

特徴量は、たとえばローリングの zスコアのように過去のデータだけを使って正規化し、モデルが将来から計算された統計量を決して見ないようにしてください。データの入手とタイムスタンプについてはマーケットデータで解説しています。

ラベリング

ラベルとはモデルが予測を学習する対象のことで、それをうまく選べるかどうかで問題の半分が決まります。

  • 固定期間ラベル： 次の N 本のバーにわたるリターンの符号や大きさ。シンプルですが、価格の経路や実際の取引がどう管理されるかを無視しています。
  • トリプルバリア・ラベル： Marcos López de Prado が2018年の著書『ファイナンス機械学習』（Advances in Financial Machine Learning）で解説した手法です。各サンプルに、上側のバリア（利益目標）、下側のバリア（ストップ）、時間制限のうちどれに最初に到達したかでラベルを付けます。実際の取引の手仕舞い方に合致しています。
  • メタラベリング： 一次モデルやルールが方向を決め、二次の機械学習モデルが一次シグナルのそれぞれが成功するかどうかを予測します。取引の絞り込みやポジションサイズの決定に使えます。

毎日計算した5日間リターンのように重なり合うラベルは、情報を共有しています。これは検証の段階で対処する必要があります。

非定常性とノイズ

金融における関係は変化します。低金利の時期に成り立っていたパターンが、金利の上昇とともに消えることがあります。多くのトレーダーが使い始める前に機能していた特徴量が、その後は機能しなくなることもあります。シグナル対ノイズ比は非常に低く、日々の方向を52%から53%の確率で正しく予測するモデルが役に立つことがある一方、日々の方向で70%の精度が出ている場合は、ほぼ間違いなくバグかデータリークを示しています。

これは、ルールベースの平均回帰やトレンドのシステムを悩ませるのと同じ相場局面（レジーム）の問題です。実践的な対処法としては、ローリングウィンドウでの再学習、よりシンプルなモデルの優先、多数の弱いシグナルの組み合わせ、そして実運用のパフォーマンスの劣化の監視があります。

リークのない検証

標準的な k分割交差検証はデータをランダムにシャッフルするため、モデルは将来のデータで学習し、過去のデータでテストすることになります。トレードでは次の方法を使います。

  • ウォークフォワード検証： 過去のデータで学習し、次の期間でテストし、前に進めていきます。
  • ギャップとパージング： ラベルがテスト期間と重なる学習サンプルを取り除き、テスト期間の後にエンバーゴ（禁止期間）のギャップを設けます。
  • 最終ホールドアウト： 開発中に一度も触れていない直近の期間です。
import numpy as np
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.model_selection import TimeSeriesSplit

def walk_forward_accuracy(X, y, horizon=5, n_splits=5):
    """X：時点 t でわかっている特徴量、y：t -> t+horizon のラベル。行は時系列順。"""
    splitter = TimeSeriesSplit(n_splits=n_splits, gap=horizon)  # gap でラベルの重なりを避ける
    scores = []
    for train_idx, test_idx in splitter.split(X):
        model = GradientBoostingClassifier(max_depth=3, n_estimators=200)
        model.fit(X[train_idx], y[train_idx])
        scores.append((model.predict(X[test_idx]) == y[test_idx]).mean())
    return np.mean(scores), np.std(scores)

学習して評価するモデルの一つひとつが新たな試行になるため、オーバーフィッティングとデータスヌーピングで扱う多重検定の問題が、より強く当てはまります。

ニュースとセンチメントへの LLM の活用

大規模言語モデルは、ニュース、決算説明会の書き起こし、開示書類、SNSの投稿を読み取り、それを構造化されたシグナルに変換できます。ポジティブかネガティブかのトーン、イベントの種類、言及された企業、あるいは人間のトレーダー向けの要約といったものです。実践的な用途としては、ニュースフローの絞り込み、イベントのタグ付け、人間よりも速く大量のテキストをスクリーニングすることが挙げられます。

重要な注意点があります。

  • 先読みによる汚染。 最近の日付までのインターネット上のテキストで学習したモデルは、過去の記事の日付以降に企業や市場が実際にどうなったかを「知っている」可能性があります。そのため、過去のニュースに対する LLM ベースのセンチメントのバックテストは、実運用よりはるかに良く見えることがあります。可能であれば、学習データのカットオフが検証期間より前のモデルを使うか、カットオフ以降のデータだけで検証してください。
  • 誤りとハルシネーション。 LLM は数字を読み間違えたり、企業を取り違えたり、細部を捏造したりすることがあります。出力、特に抽出した数値は検証してください。
  • レイテンシーとコスト。 モデルがヘッドラインを処理する頃には、高速なトレーダーがすでに動いているかもしれません。LLM のシグナルは、より長い時間軸に向いている傾向があります。
  • 混雑。 誰でも使えるモデルを誰でも入手できるニュースに適用しても、それだけで持続的なエッジが得られる可能性は低いです。

エージェントがシミュレーター内で試行錯誤を通じて取引方針を学習する強化学習は活発な研究分野ですが、シミュレーターの現実性とオーバーフィッティングの影響を特に受けやすい手法です。

計算例：精度は利益ではない

ある分類器が、株価指数ファンドの翌日の方向を、ウォークフォワード検証で53%の精度で予測するとします。上昇日と下落日の平均的な値動きは、どちらも約1.0%と仮定します。

  • 1取引あたりの期待粗リターン = 0.53 × 1.0% − 0.47 × 1.0% = 0.06%。
  • 往復コストが0.05%なら、純エッジは1取引あたり0.01%で、毎日取引すれば年間でおよそ 252 × 0.01% ≈ 2.5%（複利は無視）です。
  • 往復コストが0.10%なら、純エッジは1取引あたり−0.04%で、年間でおよそ−10%です。

しかも、同じモデルが将来も53%の精度を維持しなければなりませんが、非定常性のためにそれは不確かです。機械学習のシグナルは、コストが小さなエッジを食いつぶしにくい、回転率の低い戦略と組み合わせたときに最もうまく機能することが多いです。

よくある間違い

  • 時系列データで学習用とテスト用をランダムに分割する。 将来の情報が学習に漏れてしまいます。
  • 将来のデータを使って計算した特徴量。 サンプル全体での正規化や改定後の経済指標などです。
  • 高い精度を追い求める。 リターンに対する非常に高い精度は、たいていデータリークの兆候です。
  • 少ないデータに複雑なモデルを使う。 数年分の日足で学習したディープネットワークは、有用な観測値よりはるかに多くのパラメーターを持っています。
  • コストと回転率を無視する。 モデルが頻繁に取引しすぎると、小さなエッジは消えてしまいます。
  • 古いニュースに対する LLM のバックテストを信用する。 学習データによる汚染に対処していなければ危険です。

よくある質問

機械学習で株価を予測できますか？

機械学習はリターンの中に弱いながら統計的に有用なパターンを見つけることはできますが、価格を確実に予測することはできません。研究によれば、リターンのうち予測可能な部分は小さく、パターンは時間とともに変化します。

トレードに最適な機械学習モデルは何ですか？

唯一最適なモデルはありません。表形式のデータでは正則化線形モデルと勾配ブースティング木がよく使われる出発点で、通常はアルゴリズムよりも、ラベル、特徴量、検証方法の選択のほうが重要です。

ChatGPT などの LLM を使ってトレードできますか？

LLM はニュースの要約、センチメントの分類、コードの作成やレビューには役立ちますが、将来の価格について信頼できる洞察を持っているわけではありません。その出力は検証すべき入力の一つとして扱い、モデルの学習データに汚染されている可能性のあるバックテストには注意してください。

機械学習のトレード戦略が失敗するのはなぜですか？

よくある理由は、ノイズへの過学習、検証時のデータリーク、相場環境の変化、そして予測された小さなエッジを上回る取引コストです。

教育目的のコンテンツです。本サイトの内容は、金融・投資・法律・税務に関する助言ではありません。トレードには大きな損失リスクがあり、レバレッジ商品では入金額を超える損失が生じることがあります。ルール、手数料、プラットフォームの条件は変わります。取引の前に、ご利用の証券会社、取引所、規制当局で最新の条件をご確認ください。
