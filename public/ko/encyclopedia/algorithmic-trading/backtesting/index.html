백테스트(backtesting)는 일련의 매매 규칙을 과거 데이터에 적용해 그 전략이 어떤 성과를 냈을지 추정하는 과정입니다. 알고리즘 트레이딩의 핵심 리서치 도구이자, 스스로를 속이기 가장 쉬운 곳이기도 합니다. 신중한 백테스트는 데이터, 비용, 타이밍을 현실적으로 모델링합니다. 허술한 백테스트는 인상적인 숫자를 만들어 내지만, 그 숫자는 실제 돈이 들어가는 순간 사라집니다.

핵심 요약

  • 백테스트의 수준은 데이터의 수준을 넘지 못합니다. 가장 치명적인 두 가지 오류는 생존 편향과 미래 참조 편향입니다.
  • 수수료, 스프레드, 슬리피지는 보수적으로 모델링하십시오. 비용이 전략의 수익성 여부 자체를 결정하는 경우가 많습니다.
  • 전략이 한 번도 보지 않은 데이터를 표본 외 테스트용으로 남겨 두고, 주기적으로 재조정이 필요한 전략에는 워크포워드 분석을 쓰십시오.
  • 샤프 지수, 소르티노 지수, 최대 낙폭, 프로핏 팩터, 거래 횟수 등 여러 지표를 함께 보고 전략을 판단하십시오.
  • 좋은 백테스트는 확신을 높여 줄 뿐, 미래 성과를 보장하지는 않습니다.

백테스트의 작동 방식

가장 단순한 형태의 백테스트는 과거 데이터를 봉 하나씩 차례로 진행합니다. 각 단계에서 그 시점에 이용할 수 있었던 정보만으로 규칙이 무엇을 했을지 묻고, 가상의 주문과 체결을 기록하며, 계좌 자산을 추적합니다.

흔히 쓰는 설계는 두 가지입니다.

설계 작동 방식 장점 단점
벡터화 방식 배열 연산으로 전체 시계열의 신호와 수익률을 한 번에 계산 매우 빠르고 초기 리서치에 적합 미래 참조 편향이 끼어들기 쉽고, 주문 체결·손절·포지션 한도를 모델링하기 어려움
이벤트 기반 방식 실전 시스템처럼 각 봉이나 틱을 이벤트로 처리 주문 처리가 현실적이고, 코드를 실전매매에 재사용할 수 있는 경우가 많음 느리고 구축에 손이 많이 감

많은 리서처가 벡터화 테스트로 아이디어를 걸러 낸 뒤, 유망한 것은 이벤트 기반 시뮬레이터에서 확인합니다.

데이터 품질

나쁜 데이터는 확신에 차 있지만 의미 없는 결과를 만듭니다. 최소한 다음을 점검하고, 더 자세한 내용은 시장 데이터 문서를 참고하십시오.

  • 기업 행위(corporate actions). 주가는 분할과 배당을 반영해 수정되어야 합니다. 그렇지 않으면 백테스트가 가짜 폭락을 보게 되고 배당 수익을 놓칩니다.
  • 선물 롤오버. 연속 선물 시계열은 계약 만기 사이를 일관된 방식으로 이어 붙여야 합니다.
  • 잘못된 틱과 공백. 오류 체결 기록, 누락된 봉, 중복 레코드는 가짜 신호를 만듭니다.
  • 시간대와 타임스탬프. 거래소 시간, 현지 시간, UTC를 섞어 쓰면 신호가 몇 시간씩 밀릴 수 있습니다.
  • 봉 구성 방식. 업체마다 일봉의 마감 시각이 다를 수 있으며, 24시간 거래되는 외환과 크립토에서 특히 그렇습니다.

백테스트를 망치는 편향

생존 편향

생존 편향(survivorship bias)은 테스트 대상에 오늘날까지 존재하는 자산만 포함될 때 생깁니다. 파산하거나, 상장폐지되거나, 인수된 기업은 많은 무료 데이터셋에서 사라집니다. 현재 지수 구성 종목만으로 테스트한 전략은 승자들만으로 테스트된 셈이어서 수익률이 부풀려지며, 낙폭이 큰 주식을 사는 전략에서 특히 심합니다. 크립토도 마찬가지입니다. 무너진 수천 개의 토큰이 현재 코인 목록에서 빠져 있습니다. 해결책은 사라진 종목과 시점별(point-in-time) 지수 구성 정보를 포함한, 생존 편향이 없는 데이터셋을 쓰는 것입니다.

미래 참조 편향

미래 참조 편향(look-ahead bias)은 매매 시점에는 알 수 없었던 정보를 사용하는 것입니다. 흔한 예는 다음과 같습니다.

  • 그날 종가로 신호를 만들면서, 같은 종가에 매수했다고 가정하는 것.
  • 재무제표 데이터를 실제 공시일이 아니라 결산 기준일에 사용하는 것.
  • 미래를 포함한 전체 표본으로 계산한 통계(평균, 최댓값)로 데이터를 정규화하는 것.
  • 트레이더들이 실제로 본 최초 발표치 대신 수정된 경제 지표를 사용하는 것.

유용한 습관은 모든 신호를 봉 하나만큼 뒤로 미루는 것입니다. 그러면 봉 t에서 계산한 신호는 빨라도 봉 t+1에서 매매됩니다.

그 밖의 편향

  • 선택 편향: 이미 올랐다는 것을 아는 시장에서만 테스트하는 것.
  • 데이터 스누핑: 여러 변형을 테스트한 뒤 가장 좋은 것만 보고하는 것. 과최적화와 데이터 스누핑에서 다룹니다.
  • 유동성 편향: 얇은 시장에서 큰 규모를 호가 그대로 매매할 수 있다고 가정하는 것.

비용과 슬리피지 모델링

모든 가상 거래에 현실적인 비용을 부과해야 합니다.

  • 수수료와 거래소 수수료, 크립토 거래소의 메이커/테이커 수수료 포함.
  • 스프레드. 매도호가에 사고 매수호가에 팔면 왕복 거래마다 호가 스프레드 전체를 비용으로 치릅니다.
  • 슬리피지와 시장 충격. 시장가 주문과 손절 주문은 마지막 가격보다 불리하게 체결되는 경우가 많으며, 빠른 장세와 큰 규모에서 특히 그렇습니다.
  • 자금 조달 비용. 오버나이트 스왑, 무기한 선물의 펀딩비, 공매도 시 주식 대차 수수료.

합리적인 방법은 가능하면 실제 체결 내역으로 비용을 추정한 뒤, 그 비용의 두 배로 백테스트를 다시 돌려 보는 것입니다. 낙관적인 비용 수준에서만 통하는 전략이라면 아마 통하지 않는 전략입니다.

표본 내, 표본 외, 워크포워드

시작하기 전에 과거 데이터를 나누십시오. 표본 내(in-sample) 구간에서 전략을 만들고 조정한 뒤, 표본 외(out-of-sample) 구간에서 한 번만 테스트합니다. 규칙을 손보려고 표본 외 데이터로 계속 돌아간다면, 그 데이터는 더 이상 표본 외가 아닙니다.

워크포워드 분석(walk-forward analysis)은 이 과정을 시간 순서대로 반복합니다. 예를 들어 20152018년으로 파라미터를 최적화하고 2019년으로 테스트합니다. 이어서 20162019년으로 최적화하고 2020년으로 테스트하는 식입니다. 테스트 구간을 이어 붙이면, 전략을 실시간으로 재조정했다면 어땠을지를 반영하는 표본 외 자산 곡선이 나옵니다. 표본 내 결과와 워크포워드 결과의 차이가 크다면 과최적화를 의심해야 합니다.

성과 지표

전략을 숫자 하나로 담아낼 수는 없습니다. 여러 지표를 함께 쓰십시오.

지표 공식 알려 주는 것
CAGR (Ending equity / Starting equity)^(1 / years) − 1 연평균 복리 성장률
샤프 지수 Mean(R − Rf) / StdDev(R − Rf), √(연간 기간 수)를 곱해 연환산 전체 변동성 한 단위당 수익
소르티노 지수 (Mean(R) − T) / Downside deviation, 같은 방식으로 연환산 하방 변동성 한 단위당 수익
최대 낙폭(MDD) 자산의 고점 대비 저점까지 가장 큰 하락폭, 고점 대비 비율 과거 최악의 고통
프로핏 팩터 Gross profit / Gross loss (절댓값) 1달러 손실당 번 달러
승률과 기대값 이긴 거래의 비율, 거래당 평균 이익 수익의 분포 방식

여기서 R은 기간당 전략 수익률, Rf는 기간당 무위험 이자율, T는 목표 수익률(흔히 0)입니다. 하방 편차(downside deviation)는 모든 기간에 대해 min(0, R − T)²의 평균을 구한 뒤 제곱근을 취한 값이므로, 목표를 웃돈 기간은 0으로 계산됩니다. 일간 데이터라면 일간 비율에 √252, 약 15.87을 곱합니다. 낙폭과 회복 계산은 낙폭과 파산 위험에서, 기대값은 손익비와 기대값에서 다룹니다.

아래 함수들은 수익률 시계열, 자산 곡선, 거래별 손익 목록으로 이 지표들을 계산합니다.

import numpy as np

def sharpe(returns, rf_per_period=0.0, periods_per_year=252):
    excess = np.asarray(returns) - rf_per_period
    return np.sqrt(periods_per_year) * excess.mean() / excess.std(ddof=1)

def sortino(returns, target=0.0, periods_per_year=252):
    r = np.asarray(returns)
    downside = np.minimum(r - target, 0.0)
    downside_dev = np.sqrt(np.mean(downside ** 2))
    return np.sqrt(periods_per_year) * (r.mean() - target) / downside_dev

def max_drawdown(equity):
    equity = np.asarray(equity, dtype=float)
    peaks = np.maximum.accumulate(equity)
    return ((peaks - equity) / peaks).max()

def profit_factor(trade_pnls):
    pnl = np.asarray(trade_pnls, dtype=float)
    gross_loss = -pnl[pnl < 0].sum()
    return pnl[pnl > 0].sum() / gross_loss if gross_loss > 0 else np.inf

계산 예시

10,000달러로 시작한 전략이 다음과 같은 결과(단위: 달러)로 10번 거래했습니다: +300, −200, +150, −100, −250, +400, −150, +200, −300, +250.

  • 총이익: 300 + 150 + 400 + 200 + 250 = 1,300.
  • 총손실: 200 + 100 + 250 + 150 + 300 = 1,000.
  • 프로핏 팩터: 1,300 / 1,000 = 1.30.
  • 순이익: 300달러이므로 기대값은 거래당 30달러, 승률은 50%입니다.
  • 자산 경로: 10,300; 10,100; 10,250; 10,150; 9,900; 10,300; 10,150; 10,350; 10,050; 10,300.
  • 최대 낙폭: 고점 10,300에서 저점 9,900까지, 400 / 10,300 ≈ 3.9% 하락.

위험 조정 비율을 보기 위해, 더 긴 테스트에서 일간 평균 수익률 0.05%, 일간 표준편차 1.0%, 하방 편차 0.7%가 나왔고 무위험 이자율은 0이라고 가정합시다. 연환산 샤프 지수는 0.05 / 1.0 × 15.87 ≈ 0.79이고, 소르티노 지수는 0.05 / 0.7 × 15.87 ≈ 1.13입니다.

거래 10번으로는 이 숫자들을 전혀 믿을 수 없습니다. 대략적인 기준으로, 많은 리서처는 통계를 의미 있게 보기 전에 다양한 시장 상황에 걸친 최소 수백 건의 거래를 원합니다.

흔한 실수

  • 신호를 만든 봉에서 매매합니다. 종가로 계산한 신호는 그 종가에 체결될 수 없습니다.
  • 현재 지수 구성 종목을 씁니다. 모든 결과에 생존 편향이 끼어듭니다.
  • 비용을 0이나 아주 작게 가정합니다. 회전율이 높은 전략은 특히 민감합니다.
  • 표본 외 데이터를 재사용합니다. 한 번 들여다볼 때마다 표본 내 데이터로 바뀝니다.
  • 거래 횟수가 너무 적습니다. 큰 수익 거래 몇 건만으로도 화려하지만 의미 없는 백테스트가 나올 수 있습니다.
  • 수용 용량(capacity)을 무시합니다. 1,000달러로는 통하던 전략이 100,000달러에서는 주문이 가격을 움직이는 바람에 실패할 수 있습니다.

자주 묻는 질문

백테스트에서 좋은 샤프 지수는 어느 정도인가요?

많은 실무자는 단일 전략의 연환산 샤프 지수가 1을 넘으면 유망하다고 봅니다. 일간 전략에서 3을 넘는 것처럼 지나치게 높은 백테스트 값은 실제 엣지보다는 오류, 미래 참조 편향, 과최적화를 가리키는 경우가 더 많습니다.

백테스트에는 과거 데이터가 얼마나 필요한가요?

상승장, 하락장, 횡보장, 그리고 최소 한 번의 스트레스 구간처럼 서로 다른 시장 국면을 포함할 만큼 필요합니다. 일간 전략이라면 보통 10년 이상이고, 일중 전략이라면 거래가 많이 담겨 있는 한 더 짧은 기간으로도 충분할 수 있습니다.

백테스트와 모의매매는 무엇이 다른가요?

백테스트는 과거 데이터를 재생하는 것이고, 모의매매는 실제 돈 없이 실시간 가격으로 전략을 돌리는 것입니다. 모의매매는 백테스트가 잡아낼 수 없는 체결 문제와 소프트웨어 문제를 잡아냅니다.

실전 결과는 왜 백테스트 결과와 다른가요?

흔한 원인은 과소평가된 비용과 슬리피지, 과거 노이즈에 대한 과최적화, 데이터의 편향, 시장 행태의 변화입니다. 어느 정도의 차이는 정상이지만, 차이가 크다면 백테스트에 결함이 있었다는 뜻입니다.
